**4. You do not need to buffer the full payload just because you want compression.**  
You can compress **while writing** by using a custom `HttpContent` that, inside `SerializeToStreamAsync`, wraps the outgoing stream in `GZipStream` and then calls `JsonSerializer.SerializeAsync(gzipStream, value)`. That gives you:

- no giant UTF-16 string
- no full uncompressed `MemoryStream`
- compression on the fly
- typically no `Content-Length`, so HTTP/1.1 will usually use chunked transfer

That means the tradeoff is **not** “either low memory or compression.” You can usually have **both low memory and compression**, with the tradeoff being more like:

- lower app memory
- better network efficiency
- a bit more CPU
- often no precomputed `Content-Length`

A sketch:

sealed class GzipJsonContent<T> : HttpContent  
{  
    private readonly T _value;  
    private readonly JsonSerializerOptions? _options;  
  
    public GzipJsonContent(T value, JsonSerializerOptions? options = null)  
    {  
        _value = value;  
        _options = options;  
  
        Headers.ContentType = new System.Net.Http.Headers.MediaTypeHeaderValue("application/json");  
        Headers.ContentEncoding.Add("gzip");  
    }  
  
    protected override async Task SerializeToStreamAsync(Stream stream, TransportContext? context)  
    {  
        await using var gzip = new System.IO.Compression.GZipStream(  
            stream,  
            System.IO.Compression.CompressionLevel.Fastest,  
            leaveOpen: true);  
  
        await System.Text.Json.JsonSerializer.SerializeAsync(gzip, _value, _options);  
    }  
  
    protected override bool TryComputeLength(out long length)  
    {  
        length = 0;  
        return false;  
    }  
}

Usage:

request.Content = new GzipJsonContent<MyType>(payload);

That is the streaming version.

So the answer to your two questions is:

- **Am I sure `MemoryStream` buffers the whole payload?** Yes.
- **Am I sure `JsonContent.Create` never buffers the whole payload anywhere?** No, I would not say that absolutely. I’d say it **does not require the same upfront full-payload byte buffer that your `MemoryStream` approach does**, and in normal request sending it is the less-buffered model.

And for compression:

- **No, compression does not force you to prebuffer the full body.**
- You can compress and serialize **directly to the outgoing stream** with a custom `HttpContent`.
