## Text Elements
`git reset` moves your current branch pointer to another commit. Depending on the mode, it also changes the staging area and/or your working files.

Basic syntax:

```bash
git reset [mode] <target>
```

Common targets:

```bash
HEAD        # current commit
HEAD~1      # one commit before current
HEAD~2      # two commits before current
<commit_id> # exact commit hash
origin/branch-name # remote branch state
```

## Three reset modes

### 1. `--soft`

Moves commit history only. Keeps all changed files **staged**.

```bash
git reset --soft HEAD~1
```

Use when:

```text
I want to undo the last commit, but keep everything ready to recommit.
```

After this, `git status` will show the files as staged.

---

### 2. `--mixed`

Default mode. Moves commit history and unstages files, but keeps file changes in your folder.

```bash
git reset --mixed HEAD~1
```

Same as:

```bash
git reset HEAD~1
```

Use when:

```text
I want to undo the last commit and edit/restage files before recommitting.
```

After this, files are still on disk, but not staged.

This is the one I suggested for your case because it lets you remove `Repetition/`, add `-Repetition/`, then make a clean new commit.

---

### 3. `--hard`

Moves commit history and discards file changes from your working tree.

```bash
git reset --hard HEAD~1
```

Use when:

```text
I want to completely delete the last commit and its file changes locally.
```

Danger: this can delete uncommitted work.

## Your case

You currently have a pushed commit that added:

```text
Repetition/
```

But you wanted:

```text
-Repetition/
```

If you want to redo the last commit cleanly:

```bash
git reset --mixed HEAD~1
```

This means:

```text
Remove the last commit from local history,
but keep the files from that commit in my working folder as uncommitted changes.
```

Then you can delete wrong files and add correct ones:

```bash
rm -rf "Repetition"
unzip -o repetition_reorg_root_dash_active_shifted.zip -d .
git add -- "-Repetition"
git commit -m "Move repetition schedule to active shifted structure"
git push --force-with-lease origin ai-conspects-repetition-plan
```

## Why force push is needed after reset

You already pushed the old commit to GitHub.

After reset + new commit, your local branch history differs from GitHub history. So normal push may be rejected.

Use:

```bash
git push --force-with-lease origin ai-conspects-repetition-plan
```

`--force-with-lease` is safer than `--force`: it refuses to overwrite remote changes if someone else updated the branch after your last fetch.

## Mental model

```text
commit history = Git timeline
staging area   = what will go into next commit
working tree   = actual files in your folder
```

Reset modes:

```text
--soft  = change history only
--mixed = change history + unstage
--hard  = change history + unstage + overwrite files
```

For “redo last commit but keep work,” use:

```bash
git reset --mixed HEAD~1
```
