Да, я бы **сначала сделал OpenAPI + генерацию client constants**, и только потом начинал доделывать клиентские слайсы. Иначе сейчас клиентская часть будет продолжать руками угадывать routes/DTO/error contract.

По текущему репо это особенно актуально: backend уже имеет `Swashbuckle.AspNetCore`, `AddEndpointsApiExplorer()` и `AddSwaggerGen()`, а Swagger включается в Development.  
При этом старый constants writer фактически уже отключался/закомментирован в `Program.cs`, а `ErrorObject.Create()` ещё регистрируется как singleton.

## Цель

Разделить контракт на две части:

```text
OpenAPI:
- endpoints
- HTTP methods
- request DTO
- response DTO
- status codes
- ProblemDetails response shape

Generated constants JSON:
- stable human-readable error codes
- ProblemDetails extension names
- ServerError / ServerValidationError field names
- возможно route constants временно, пока client не перешёл на OpenAPI-generated client
```

OpenAPI не должен заменять error-code constants. OpenAPI хорошо описывает форму API, но конкретные доменные error codes лучше держать как отдельный generated artifact.

# Шаг 3. Настроить OpenAPI quality

Минимально нужно:

```text
1. Все client-facing DTO должны быть public и попадать в schema.
2. Все client-facing endpoints должны иметь понятные route/method.
3. Для каждого endpoint желательно явно описать response types.
4. Error responses должны быть ProblemDetails.
5. OperationId должен быть стабильным.
```

Для контроллеров добавить атрибуты примерно такого уровня:

```csharp
[ProducesResponseType(typeof(L1RegisterClientAccountResponse), StatusCodes.Status200OK)]
[ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status422UnprocessableEntity)]
[ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status500InternalServerError)]
```

Для protected endpoints:

```csharp
[ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status401Unauthorized)]
[ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status403Forbidden)]
```

Это нужно не ради красоты Swagger UI, а чтобы generated client/types не были бесполезными.

# Шаг 4. Сгенерировать `Shared/openapi.json`

Есть два варианта.

## Вариант A — через running server

Команда примерно:

```bash
dotnet run --project EnergyManagement.Server/EnergyManagement.Server.csproj
```

потом:

```bash
curl -k https://localhost:7250/swagger/v1/swagger.json -o Shared/openapi.json
```

Плюс: просто и совпадает с runtime.

Минус: хуже для CI/check mode, нужно поднимать сервер.

## Вариант B — через Swashbuckle CLI

Добавить local tool manifest и Swashbuckle CLI:

```bash
dotnet new tool-manifest
dotnet tool install Swashbuckle.AspNetCore.Cli
```

После build:

```bash
dotnet build EnergyManagement.Server/EnergyManagement.Server.csproj
dotnet swagger tofile \
  --output Shared/openapi.json \
  EnergyManagement.Server/bin/Debug/net8.0/EnergyManagement.Server.dll \
  v1
```

Плюс: лучше для генерации/check в pipeline.

Минус: иногда надо настраивать startup/config, если приложение при старте требует БД/секреты.

Я бы начал с **варианта A**, чтобы быстро получить JSON, потом перейти к CLI, если не будет проблем.

# Шаг 6. Сделать explicit constants generator tool

Создать отдельный project:

```text
EnergyManagement.Tools/
  Program.cs
  ClientConstants/
    GenerateClientConstantsCommand.cs
    ClientConstantsSnapshotFactory.cs
    ClientConstantsArtifacts.cs
    ClientConstantsJsonSerializer.cs
    ClientConstantsWriter.cs
    ClientConstantsChecker.cs
```

Команды:

```bash
dotnet run --project EnergyManagement.Tools -- generate-client-constants --out Shared
```

и check mode:

```bash
dotnet run --project EnergyManagement.Tools -- generate-client-constants --out Shared --check
```

Обычный режим:

```text
C# constants
-> snapshot
-> stable JSON
-> write Shared/constants.json and Shared/errorcodes.json
```

Check mode:

```text
C# constants
-> snapshot
-> stable JSON in memory
-> compare with existing Shared/*.json
-> exit 1 if outdated
-> do not modify files
```

Важно: `--check` — это не встроенная dotnet-функция. Это твой режим команды.

# Шаг 7. Разделить contents generated constants

`constants.json` должен содержать только то, что пока реально нужно клиенту и не покрыто OpenAPI.

После OpenAPI routes могут постепенно уйти из `constants.json`.

Целевая логика:

```text
OpenAPI:
- route path
- request body shape
- response body shape

constants.json:
- ProblemDetails extension names
- maybe client UI field names if они пока server-driven
- maybe legacy route constants until migration finished

errorcodes.json:
- stable client-facing error codes
- ServerValidationError field names
```

Сейчас клиент читает `Shared/constants.json` и `Shared/errorcodes.json` через `globConstants.ts`. Это можно оставить, но постепенно уменьшать роль `globConstants.ts`.

# Главное решение

Перед реализацией нужно явно принять:

```text
OpenAPI is the source for DTO/API shape.
Generated constants JSON is the source for stable semantic constants not represented well by OpenAPI.
No generated client artifact is written during normal server startup.
All generated artifacts are produced by explicit commands and checked in.
```

После этого клиентские слайсы будет проще доделывать: они будут использовать не “ручные догадки”, а contract artifacts.
