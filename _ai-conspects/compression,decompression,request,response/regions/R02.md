## S-012

**Manual middleware declaration and gzip detection.**

```csharp
public sealed class ManualGzipRequestDecompressionMiddleware
{
    private readonly RequestDelegate _next;

    public ManualGzipRequestDecompressionMiddleware(RequestDelegate next)
        => _next = next;

    public async Task InvokeAsync(HttpContext context)
    {
        var encodings = context.Request.Headers.ContentEncoding;
        var isGzip = encodings.Any(h =>
            h.Contains("gzip", StringComparison.OrdinalIgnoreCase));
    }
}
```

---

## S-013

**Nuance: multiple encodings.** Wrapping the body once in `GZipStream` can be wrong or incomplete when `Content-Encoding` contains multiple codings. The codings must be decoded in the correct reverse order.

---

## S-011

**Manual middleware wrapper creation.** If the request is not gzip, continue unchanged. Otherwise save the original stream and create a `GZipStream`. The source first demonstrates `leaveOpen: false`, then later explains why `true` is the safer middleware ownership convention.

```csharp
if (!isGzip)
{
    await _next(context);
    return;
}

var originalBody = context.Request.Body;
var gzipStream = new GZipStream(
    originalBody,
    CompressionMode.Decompress,
    leaveOpen: false);
```

---

## S-014

**Why `leaveOpen: false` is a concern.** Disposing `gzipStream` also closes `originalBody`. Better middleware ownership: use `leaveOpen: true`, dispose only the wrapper created by the middleware, then restore `Request.Body`.

---

## S-010

**Manual middleware cleanup, second half.** Assign the gzip wrapper to `Request.Body`, optionally remove `Content-Encoding`, call the next middleware, then dispose the wrapper and restore the original body in `finally`.

```csharp
context.Request.Body = gzipStream;
context.Request.Headers.Remove("Content-Encoding");

try
{
    await _next(context);
}
finally
{
    await gzipStream.DisposeAsync();
    context.Request.Body = originalBody;
}
```

---

## S-015

**Improved middleware start.** Read `Content-Encoding` using `HeaderNames.ContentEncoding`; if it is absent, call `_next` and return.

```csharp
var encodings = context.Request.Headers[HeaderNames.ContentEncoding];

if (encodings.Count == 0)
{
    await _next(context);
    return;
}
```

## S-016

**Simple single-encoding policy.** Require exactly one `gzip` coding. Otherwise return `415 Unsupported Media Type`.

```csharp
if (encodings.Count != 1 ||
    !encodings[0]!.Equals("gzip", StringComparison.OrdinalIgnoreCase))
{
    context.Response.StatusCode =
        StatusCodes.Status415UnsupportedMediaType;
    return;
}

var originalBody = context.Request.Body;
```

## S-017

**Safer wrapper continuation.** Create `GZipStream` with `leaveOpen: true`, assign it to `Request.Body`, remove the now-consumed `Content-Encoding` header, call downstream middleware, then restore the original body.

```csharp
await using var gzipStream = new GZipStream(
    originalBody,
    CompressionMode.Decompress,
    leaveOpen: true);

context.Request.Body = gzipStream;
context.Request.Headers.Remove(HeaderNames.ContentEncoding);

try
{
    await _next(context);
}
finally
{
    context.Request.Body = originalBody;
}
```

## S-050

**`Request.Body` is a stream.** ASP.NET Core exposes the request body as `HttpRequest.Body` (`Stream`), so it can be wrapped in `GZipStream` for decompression.

---

## S-045

**Why closing `originalBody` is a concern.** `Request.Body` belongs to ASP.NET Core/server pipeline; the decompression wrapper belongs to custom middleware. Middleware should dispose what it creates, not the framework-owned underlying stream.

---

## S-051

**Why cleanup is in `finally`.** The middleware created the wrapper and must dispose it even if model binding, a controller, or downstream middleware throws.

---

## S-049

**Why ownership clarity matters.** Disposing a resource the middleware did not create is brittle. It can fail after middleware reordering, added logging/tracing, exception inspection, or a different host/server implementation.

---

## S-052

**Cleanup code.**

```csharp
try
{
    await _next(context);
}
finally
{
    await gzipStream.DisposeAsync();
    context.Request.Body = originalBody;
}
```

---

## S-046

**Multiple wrappers scenario.** Request bodies may be wrapped for buffering, decompression, size limits, or logging. One wrapper unexpectedly closing the underlying stream can break cleanup/finalization in another wrapper. `leaveOpen: true` avoids that coupling.

---

## S-047

**Pipeline may still touch the body indirectly.** Diagnostics, exception middleware, later custom middleware, or buffering/rewind logic may inspect it after `_next`. Closing the underlying stream can break those components.

---

## S-048

**Safer convention.** Use `leaveOpen: true`, dispose the wrapper, and restore `Request.Body`. This cleans up custom resources while leaving framework-owned lifetime with the framework.
