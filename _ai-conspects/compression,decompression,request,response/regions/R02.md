## Screenshot-backed transcript

This region verifies a custom request-decompression middleware and its ownership rules.

- Read `Content-Encoding`, decide whether the request is supported and wrap `HttpRequest.Body` with the appropriate decompression stream.
- Save the original body reference, replace it only for the downstream pipeline, and restore it in `finally`.
- The middleware owns the wrapper it creates, but the server pipeline owns the original request stream. Therefore the safe convention is `leaveOpen: true`, dispose the wrapper, and never dispose the original framework-owned stream.
- Cleanup belongs in `finally` because model binding, controllers, later middleware or diagnostics may throw.
- Closing the underlying body can break later wrappers, buffering, logging or request-body inspection even when a simple test appears to work.
- A single `GZipStream` is insufficient when multiple content codings are present; codings must be decoded in the correct reverse order.
