## Screenshot-backed transcript

This region implements layered request decompression instead of treating `Content-Encoding` as a single token.

- Parse all header entries and comma-separated values while preserving order.
- Encodings are applied by the sender in sequence and must be removed in reverse order.
- Each supported coding is represented by an `IRequestBodyDecompressor` implementation (`gzip`, `br`, `deflate`) that creates a wrapper with `leaveOpen: true`.
- A registry is built from `IEnumerable<IRequestBodyDecompressor>` and performs case-insensitive lookup.
- Unsupported codings return `415 Unsupported Media Type` rather than silently passing compressed bytes downstream.
- Track every created wrapper and dispose them in reverse/creation-safe order, then restore the original `Request.Body`.
- Middleware dependencies can be constructor-injected when singleton-safe or method-injected into `InvokeAsync`/`Invoke` for request-scoped services. Arbitrary methods do not receive automatic DI parameters.
- Registration includes all decompressor implementations, the registry and the middleware before endpoint execution.
