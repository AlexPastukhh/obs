## S-053

**Why check all `Content-Encoding` values.** A request can contain layered codings such as `Content-Encoding: gzip, br`; order matters because the body was encoded sequentially.

---

## S-054

**Why `.Any(...gzip...)` was used and its limitation.** Headers may be absent, single-valued, multi-valued, or split across entries. “Any value contains gzip” is simple detection, but wrapping once is wrong for layered codings.

## S-055

**Multiple compression layers.** HTTP permits them although they are uncommon. Conceptually: JSON → gzip → Brotli. The server removes Brotli first, then gzip.

## S-064

**Why registry injection works.** `Invoke/InvokeAsync` is a special method called by ASP.NET Core; its additional parameters are resolved from DI regardless of singleton/scoped/transient lifetime. This is not general-purpose method injection.

## S-056

**Registry contract.**

```csharp
public interface IRequestBodyDecompressorRegistry
{
    bool TryGet(
        string encoding,
        out IRequestBodyDecompressor decompressor);
}

public sealed class RequestBodyDecompressorRegistry
    : IRequestBodyDecompressorRegistry
{
    private readonly Dictionary<string, IRequestBodyDecompressor> _map;

    public RequestBodyDecompressorRegistry(
        IEnumerable<IRequestBodyDecompressor> decompressors)
    {
        _map = decompressors.ToDictionary(
            d => d.EncodingName,
            d => d,
            StringComparer.OrdinalIgnoreCase);
    }

    public bool TryGet(
        string encoding,
        out IRequestBodyDecompressor decompressor)
        => _map.TryGetValue(encoding, out decompressor!);
}
```

## S-022

**Decode in reverse order.** Iterate from the last `Content-Encoding` to the first. Resolve each decompressor through the registry; on an unsupported coding return `415` with an explanatory body; otherwise wrap the current stream and remember the wrapper.

```csharp
for (var i = encodings.Count - 1; i >= 0; i--)
{
    var encoding = encodings[i];

    if (!registry.TryGet(encoding, out var decompressor))
    {
        context.Response.StatusCode =
            StatusCodes.Status415UnsupportedMediaType;
        await context.Response.WriteAsync(
            $"Unsupported Content-Encoding: {encoding}");
        return;
    }

    var wrapped = decompressor.WrapDecompressionStream(current);
    wrappers.Add(wrapped);
    current = wrapped;
}
```

## S-060

**Middleware injection rules.** Constructor injection is resolved when regular middleware is created. Extra parameters on `Invoke`/`InvokeAsync` are resolved per request. This framework-supported method injection is useful for scoped/request-specific dependencies.

## S-021

**Layered middleware completion.** After wrapping the stream for every coding, assign the final wrapper to `Request.Body`, remove `Content-Encoding`, invoke downstream code, restore the original body, and dispose all created wrappers in reverse order.

```csharp
context.Request.Body = current;
context.Request.Headers.Remove(HeaderNames.ContentEncoding);

await _next(context);

context.Request.Body = originalBody;

for (var i = wrappers.Count - 1; i >= 0; i--)
    await wrappers[i].DisposeAsync();
```

## S-005

**When to use response compression.** Good when JSON/text responses are medium or large, bandwidth matters, or clients use slower/mobile links. Usually avoid recompressing JPEG, PNG, MP4, ZIP, and many PDFs because they are already compressed.

---

## S-006

**When to use request compression.** More selective: very large JSON payloads, slow networks, and a server known to support decompression. It is often used only when client and server are both controlled.
