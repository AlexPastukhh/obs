## Screenshot-backed transcript

This region covers what `AddDataProtection()` provides and how production key management affects reliability.

- Data Protection performs authenticated protection: confidentiality plus integrity/tamper detection, not raw encryption alone.
- The key ring contains active and retained keys. A protected payload records key/algorithm metadata and can still be unprotected with an older retained key.
- A KDF derives purpose-specific subkeys from the master key and purpose chain; unrelated purposes do not share working keys.
- `Unprotect` can throw `CryptographicException` for tampering, corruption, wrong purpose, unavailable key ring or expiry. Treat client-provided failures as invalid input at a boundary rather than leaking details.
- Persist keys to stable shared storage. Ephemeral container filesystems or separate per-instance rings invalidate cookies/tokens after restart or across nodes.
- Protect the key ring at rest with the hosting-appropriate mechanism: Windows DPAPI, a shared certificate/private key, managed key service or protected external store.
- Key rotation is normally automatic. Losing keys is destructive; changing application name/purpose/store also changes the isolation boundary.
- Framework consumers include authentication cookies, Identity cookies, antiforgery and TempData, which generally translate invalid protected data into their own normal outcomes.
