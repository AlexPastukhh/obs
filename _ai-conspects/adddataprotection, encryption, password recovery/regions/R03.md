## Screenshot-backed transcript

This region reconstructs a complete password-recovery flow.

- Generate a token containing only the minimum trusted data needed later, typically a user identifier plus an invalidation marker such as a security stamp/version.
- Protect it with a dedicated password-reset purpose and an `ITimeLimitedDataProtector`.
- Encode protected bytes/text for URL transport with Base64Url rather than assuming arbitrary protected text is safe inside a link.
- Email the link, show a reset form on GET, and post the token with the new password.
- On submission, decode, `Unprotect`, handle invalid/expired input without revealing sensitive diagnostics, load the user and verify any embedded invalidation marker.
- Reset the password and invalidate outstanding links when required, for example by changing the security stamp or maintaining explicit one-time token state.
- A reusable token service keeps purpose, lifetime, serialization and validation consistent across generation and consumption.
