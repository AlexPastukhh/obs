## Screenshot-backed transcript

This region establishes the isolation model of ASP.NET Core Data Protection.

- A protector is not “named” in the security-principal sense; its purpose string/purpose chain becomes part of the cryptographic context.
- Protectors created from the same key ring can only read each other’s payloads when their purpose chains are identical.
- Stable, explicit purposes provide domain separation, versioning and protection against cross-use between unrelated token types.
- A purpose-specific singleton service can centralize the correct purpose and avoid scattering strings through handlers. A narrow application interface is preferred over pretending that `IDataProtector` itself has domain semantics.
- Multiple arguments to `CreateProtector` are a purpose chain and are conceptually equivalent to chained `CreateProtector` calls.
- `ITimeLimitedDataProtector` embeds and enforces expiry in the protected payload; this is safer than manually trusting an expiry field after ordinary `Unprotect`.
- Time-limited protectors can themselves create more purpose-specific protectors.
