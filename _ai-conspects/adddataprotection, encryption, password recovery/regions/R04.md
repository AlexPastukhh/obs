## Screenshot-backed transcript

This region chooses the primitive according to whether the original value must be recovered.

- **Hashing is one-way** and is appropriate for passwords, API-key verification, refresh-token lookup and integrity comparisons. Store a hash plus the metadata needed to verify it.
- **Encryption/Data Protection is reversible** and is used when the application must recover trusted payload data: protected tokens, framework cookies, temporary browser state or stored external access tokens.
- A hashing-style token design usually stores token state server-side, enabling individual revocation, usage tracking and strict one-time semantics.
- A Data Protection token can carry the state in a protected, purpose-isolated, time-limited payload, reducing database lookup and custom parsing.
- A normal signed JWT (JWS) is readable but integrity-protected. Its signature is typically a keyed MAC such as HMAC-SHA256 or a public-key signature; it is not payload encryption.
- An encrypted JWT (JWE) adds confidentiality and is a different format/requirement.
