## Screenshot-backed transcript

This region combines Identity storage and validation with a custom JWT bearer surface.

- Keep users, passwords, roles and claims in Identity/EF stores, but issue an API JWT after validating credentials through `UserManager`/`SignInManager`.
- Build token claims from stable identity claims, user claims, role names and optionally role claims; remove duplicate type/value pairs.
- Configure issuer, audience, signing key, lifetime and `JwtBearer` token validation consistently.
- Protect API endpoints with bearer authentication and authorization; SPA clients send `Authorization: Bearer ...`.
- Browser token storage has XSS implications; persisting a bearer token is a security decision, not just a convenience.
- Newer Identity API endpoints can expose built-in registration/login/account flows without scaffolding every controller, while exact endpoint shapes depend on the framework version.
