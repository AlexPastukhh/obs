## Screenshot-backed transcript

This region covers the browser-facing security flows around Identity.

- Identity confirmation/reset tokens must be Base64Url-encoded for links and decoded before validation. Use HTTPS, do not log tokens and preserve their purpose/lifetime semantics.
- Lockout is built into Identity through access-failure counters, lockout end/enabled fields and `CheckPasswordSignInAsync(..., lockoutOnFailure: true)`. This is account lockout, not a general endpoint rate limiter.
- Configure allowed failures and lockout duration deliberately; password hashing remains the framework’s responsibility rather than custom password storage.
- External login starts by returning `Challenge` for the registered provider scheme. The handler builds the provider redirect and anti-forgery `state`.
- In the callback, read external-login info, find a linked local account or create/link one, then issue the local Identity sign-in cookie.
- `LoginProvider` identifies the provider; `ProviderKey` is that provider’s stable subject/user key. Identity stores these in `AspNetUserLogins`.
- Common failures include missing `UseAuthentication`, nonexistent cookie paths, anonymous access to protected actions, missing role setup and broken token URL encoding.
