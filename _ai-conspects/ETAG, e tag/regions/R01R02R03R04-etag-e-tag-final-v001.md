# R01 — ETag basics and conditional GET

## What an ETag represents

An entity tag is a validator for one representation of a resource.

Example response:

```http
HTTP/1.1 200 OK
ETag: "abc123"
Last-Modified: Wed, 08 Apr 2026 10:00:00 GMT
Cache-Control: private, no-cache
```

A strong ETag is normally an opaque quoted value:

```http
ETag: "abc123"
```

A weak validator has the `W/` prefix:

```http
ETag: W/"abc123"
```

Strong validators are suitable for byte-level or exact-version comparison. Weak validators indicate semantic equivalence and are mainly useful for cache validation.

ETag values must be quoted according to HTTP syntax.

## Conditional GET

A browser or cache that has stored a previous representation may revalidate it:

```http
GET /api/products/5
If-None-Match: "abc123"
```

When the current validator matches, the server can return:

```http
HTTP/1.1 304 Not Modified
ETag: "abc123"
```

A `304` response has no normal representation body. The client reuses its cached copy.

When the validator does not match, the server returns the current representation, usually with `200 OK` and a new ETag.

## `If-None-Match` and `If-Modified-Since`

When both are present for cache validation, ETag-based validation is preferred:

```text
1. evaluate If-None-Match
2. fall back to If-Modified-Since only when ETag validation is unavailable
```

ETags are usually more precise than timestamps.

## ASP.NET Core without Output Cache

Simply adding:

```csharp
Response.GetTypedHeaders().ETag =
    new EntityTagHeaderValue("\"product-123-v7\"");
```

does not automatically make ASP.NET Core compare a later `If-None-Match` request header.

Without Output Cache or custom conditional logic, the application must perform the comparison and return `304` itself.

## Output Cache

Output Cache can store a response together with its validators and evaluate later conditional requests.

Conceptual flow:

```text
first request
    endpoint executes
    response is cached with ETag

later If-None-Match request
    Output Cache finds a fresh cached entry
    cached ETag matches request validator
    middleware returns 304
    endpoint may not execute
```

Output Cache validates against the cached representation. It does not query the database merely to discover whether the underlying row changed.

Invalidation, expiration and cache policy determine when the cached representation is refreshed.

## `Cache-Control: private, no-cache`

For authenticated/user-specific responses, a common policy is:

```http
Cache-Control: private, no-cache
```

Meaning:

```text
private
    do not store in a shared intermediary cache

no-cache
    storage is allowed, but the response must be revalidated before reuse
```

`no-cache` does not mean “never store.” `no-store` means “do not store.”

# R02 — EF Core rowversion and optimistic-concurrency preconditions

## SQL Server `rowversion`

A SQL Server `rowversion` column is:

```text
generated by SQL Server
changed whenever that row is updated
not manually incremented by EF Core
well suited as an optimistic-concurrency token
```

Entity mapping with an attribute:

```csharp
public sealed class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = null!;
    public decimal Price { get; set; }

    [Timestamp]
    public byte[] RowVersion { get; set; } = null!;
}
```

Fluent configuration:

```csharp
modelBuilder.Entity<Product>()
    .Property(product => product.RowVersion)
    .IsRowVersion();
```

The database value can be encoded as a quoted Base64 ETag.

## ETag helper

```csharp
public static class ETagUtil
{
    public static EntityTagHeaderValue ToETag(
        byte[] rowVersion)
    {
        var token = Convert.ToBase64String(rowVersion);
        return new EntityTagHeaderValue($"\"{token}\"");
    }

    public static bool IfNoneMatchSatisfied(
        HttpRequest request,
        EntityTagHeaderValue current)
    {
        var values = request.GetTypedHeaders().IfNoneMatch;

        if (values is null || values.Count == 0)
            return false;

        return values.Any(value =>
            value.Tag == "*" || value.Tag == current.Tag);
    }
}
```

Comparison logic should support:

```text
multiple validators
wildcard *
quoted syntax
strong/weak comparison rules appropriate for the operation
```

## GET with ETag

```csharp
[HttpGet("{id:int}")]
public async Task<IActionResult> GetById(int id)
{
    var product = await db.Products
        .AsNoTracking()
        .SingleOrDefaultAsync(item => item.Id == id);

    if (product is null)
        return NotFound();

    var etag = ETagUtil.ToETag(product.RowVersion);

    if (ETagUtil.IfNoneMatchSatisfied(Request, etag))
    {
        Response.GetTypedHeaders().ETag = etag;
        return StatusCode(StatusCodes.Status304NotModified);
    }

    Response.GetTypedHeaders().ETag = etag;
    Response.Headers.CacheControl = "private, no-cache";

    return Ok(new ProductDto(
        product.Id,
        product.Name,
        product.Price));
}
```

A `304` response should still include the relevant validator.

## `If-Match` for PUT/PATCH/DELETE

For optimistic concurrency:

```http
If-Match: "stored-etag"
```

Meaning:

```text
perform the mutation only if the resource is still this version
```

Recommended outcomes:

```text
If-Match missing when required
    428 Precondition Required

If-Match does not match current version
    412 Precondition Failed

database version changes after the initial check
    catch DbUpdateConcurrencyException
    return 412
```

Example shape:

```csharp
var currentEtag = ETagUtil.ToETag(product.RowVersion);

if (!ETagUtil.IfMatchSatisfied(
        Request,
        currentEtag,
        out var missingIfMatch))
{
    return missingIfMatch
        ? StatusCode(StatusCodes.Status428PreconditionRequired)
        : StatusCode(StatusCodes.Status412PreconditionFailed);
}

product.Name = dto.Name;
product.Price = dto.Price;

try
{
    await db.SaveChangesAsync();
}
catch (DbUpdateConcurrencyException)
{
    return StatusCode(
        StatusCodes.Status412PreconditionFailed);
}

Response.GetTypedHeaders().ETag =
    ETagUtil.ToETag(product.RowVersion);

return NoContent();
```

The preliminary comparison improves the response, while EF's concurrency check protects against a race between the read and `SaveChanges`.

## EF original value

For a configured concurrency token, EF remembers the original value loaded with the entity.

SQL update logic conceptually includes:

```sql
UPDATE Products
SET Name = @name
WHERE Id = @id
  AND RowVersion = @originalRowVersion
```

When zero rows are affected, EF throws `DbUpdateConcurrencyException`.

## Create-only semantics

For a client-chosen identifier or upsert-style PUT:

```http
If-None-Match: *
```

means:

```text
perform the operation only if no current representation exists
```

This prevents accidentally overwriting an existing resource.

## Relevant status codes

```text
200 OK
    representation returned

204 No Content
    mutation succeeded without a response body

304 Not Modified
    GET validator matched; reuse cached representation

409 Conflict
    domain/business conflict, not merely a validator mismatch

412 Precondition Failed
    If-Match or another supplied precondition failed

428 Precondition Required
    server requires a precondition such as If-Match
```

# R03 — aggregate-level ETags and child changes

## Aggregate root as the concurrency boundary

When child entities may only be changed through an aggregate root, a single aggregate version often matches the domain model.

Example:

```text
Order
  └─ OrderLines

Student
  └─ Enrollments
```

The client reads the aggregate with version `V1`, changes one enrollment or line, and submits the aggregate version with the mutation.

If another operation changed any part of the aggregate first, the version mismatch rejects the stale write.

## Root rowversion limitation

SQL Server updates a rowversion only when that particular row is updated.

If only an `OrderLine` row changes:

```text
OrderLines.RowVersion changes, when configured there
Orders.RowVersion does not automatically change
```

EF knowing that a child changed does not make SQL Server update the parent row.

Therefore, a root-only rowversion does not protect the whole aggregate unless every aggregate mutation also updates the root.

## Application-managed aggregate version

Use a real root property such as:

```csharp
public Guid AggregateVersion { get; private set; }
```

or:

```csharp
public long AggregateVersion { get; private set; }
```

Configure it as a concurrency token:

```csharp
builder.Property(order => order.AggregateVersion)
    .IsConcurrencyToken();
```

When a child changes, bump the root value so an actual root-row `UPDATE` occurs:

```csharp
order.AggregateVersion = Guid.NewGuid();
```

This makes the aggregate ETag reflect child mutations.

## Detect changed aggregates

Conceptual sequence before saving:

```text
find directly changed aggregate roots
find changed child entities that belong to an aggregate
resolve each child's aggregate root
deduplicate roots
bump each root version once
save all changes
```

Pseudo-code:

```csharp
var changedRootIds = ChangeTracker
    .Entries<Order>()
    .Where(entry =>
        entry.State is EntityState.Added
            or EntityState.Modified
            or EntityState.Deleted)
    .Select(entry => entry.Entity.Id);

var changedRootIdsFromChildren = ChangeTracker
    .Entries<OrderLine>()
    .Where(entry =>
        entry.State is EntityState.Added
            or EntityState.Modified
            or EntityState.Deleted)
    .Select(entry => entry.Entity.OrderId);

var rootIds = changedRootIds
    .Concat(changedRootIdsFromChildren)
    .Distinct()
    .ToList();

foreach (var orderId in rootIds)
{
    var orderEntry = ChangeTracker
        .Entries<Order>()
        .SingleOrDefault(entry =>
            entry.Entity.Id == orderId);

    if (orderEntry is null)
        continue;

    orderEntry.Entity.BumpVersion();
    orderEntry.Property(
        order => order.AggregateVersion)
        .IsModified = true;
}
```

## SaveChanges interceptor

When several aggregate types need the same convention, a `SaveChangesInterceptor` can centralize the behavior:

```text
inspect the change tracker
map changed child types to aggregate roots
load/resolve roots when required
bump one version per distinct root
allow SaveChanges to continue
```

The mapping between child type and root should be explicit. Avoid an opaque “toggle shadow boolean” when a meaningful version property is easier to understand and expose as an ETag.

## Direct root changes

Include roots changed directly as well as roots referenced by changed children:

```text
roots with Added/Modified/Deleted state
UNION
roots containing changed child entities
```

Bump each aggregate once.

## Aggregate ETag choice

Two common approaches:

```text
database rowversion
    excellent when every aggregate change causes a root-row update

application-managed version
    useful when child changes must intentionally bump the root
```

The ETag should correspond to the actual consistency boundary clients are editing.

# R04 — browser, SPA and manual validator lifecycle

## Browser behavior

For ordinary browser cache revalidation, a browser/cache may automatically store a response validator and later send:

```http
If-None-Match: "etag"
```

This behavior depends on cache policy, request method, browser cache state and fetch options.

The browser does not automatically manage optimistic-concurrency `If-Match` headers for API writes.

## SPA flow

For PUT/PATCH/DELETE:

```text
1. GET the resource
2. read ETag from the response
3. store the ETag with the loaded entity/edit state
4. send it later as If-Match
5. handle 412/428
6. replace the stored ETag with the new response ETag after success
```

JavaScript example:

```javascript
const response = await fetch("/api/products/5");
const product = await response.json();
const etag = response.headers.get("ETag");

await fetch("/api/products/5", {
  method: "PATCH",
  headers: {
    "Content-Type": "application/json-patch+json",
    "If-Match": etag
  },
  body: JSON.stringify(patchDocument)
});
```

The frontend must preserve the validator itself, for example in component state, an edit model or client-side cache.

## `useState` and rerenders

In React, an ETag loaded with the resource can live in state:

```text
resource state
etag state
```

Setting ETag state causes a render like other state updates. A mutable ref can avoid rerendering when the value is purely request metadata, but the simpler design is usually to keep the resource and its validator together in the edit state.

## Response headers in browser JavaScript

Cross-origin browser code can read `ETag` only when CORS exposes the response header:

```csharp
policy.WithExposedHeaders("ETag");
```

For same-origin requests, the response header is normally available subject to the Fetch API rules.

## Cache validation versus optimistic concurrency

```text
If-None-Match on GET
    can I reuse my cached response?

If-Match on PUT/PATCH/DELETE
    apply this mutation only if the resource is unchanged
```

They use related validators but solve different problems.

A cached GET response and its automatic browser revalidation do not automatically protect a later API mutation.

## Practical guidance

```text
[ ] quote ETag values correctly
[ ] prefer strong ETags for optimistic concurrency
[ ] send ETag on 200/304 and after successful writes when useful
[ ] require If-Match for write endpoints when stale overwrite must be prevented
[ ] use 428 when the required precondition is missing
[ ] use 412 when the supplied validator fails
[ ] retain EF/database concurrency checks after the HTTP precondition check
[ ] use If-None-Match: * for create-only semantics
[ ] configure cache policy intentionally
[ ] expose ETag through CORS for cross-origin SPA clients
[ ] ensure aggregate versions change when any protected child changes
```
