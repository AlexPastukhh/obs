## Semantic transcript

This region expands text storage choices and then shows the progression from an implicit many-to-many join table to explicitly configured or CLR-backed join entities.

## Character sets and collations

- ASCII covers a narrow character set; ISO-8859 families extend it for selected languages; Unicode provides a common character repertoire.
- `nvarchar` is the safe default for human text, multilingual content and arbitrary user input.
- `varchar` is suitable for intentionally constrained data and can also hold Unicode under a UTF-8 collation.
- The database default collation normally flows to columns unless model or migration configuration overrides it.
- Explicit collations are justified by compatibility, case/accent requirements, legacy schemas or storage decisions, not as routine decoration on every property.

## Why EF Core needs value-generation metadata

- EF Core must know whether a key or property value is supplied by the application, generated by the database or generated by the client.
- That metadata influences INSERT/UPDATE column lists, temporary keys, change tracking and whether a returned database value is expected.
- Identity and HiLo both generate keys, but identity usually returns a value after insert while HiLo can allocate it before insert.

## HiLo setup

- A model-level HiLo sequence can be shared by multiple entity types.
- A property-level configuration can select a sequence when only particular keys should use the strategy.
- The sequence provides the high component; the application generates values within the reserved range.

## Many-to-many configuration choices

- Convention-based skip navigations are appropriate when the join table has only the two foreign keys and no domain behavior.
- An explicit shared join configuration is useful when table name, foreign-key names or column names must match a database contract.
- A dedicated CLR join entity is appropriate when the relationship carries payload columns, methods, validation or navigation behavior.
- The explicit join mapping must keep the two relationships, composite or surrogate key, table name and payload configuration consistent.

## Caveats

- Using a dedicated join entity is a domain decision, not a requirement for every many-to-many relationship.
- A shared HiLo sequence intentionally interleaves numbers across participating tables.
