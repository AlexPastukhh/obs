## Structured transcript

### Form and AJAX submission

Auto-generated hidden request tokens for forms and manual token/header submission for AJAX or SPA requests.

### Why tokens work

The server validates a cookie token plus request token in the current user/request context, preventing an attacker from forging the matching pair.

### Token refresh lifecycle

Fetch a new request token after login/logout or page refresh, before rare critical writes, or after a recognized invalid-token response.

### Cross-tab and stale-token issues

Old request tokens can fail after cookie/user-context changes; refetch deliberately from the trusted client rather than adding opaque server-side auto-retry behavior.

### CORS and origin checks

Strong CORS and credential rules remain important; an optional Origin check can be defense in depth but does not replace antiforgery validation.

### MVC filters and errors

ValidateAntiForgeryToken, AutoValidateAntiforgeryToken, filter-factory behavior, exception/result handling and distinguishing antiforgery 400 responses.

### Manual validation

Direct IAntiforgery validation where necessary, with explicit error mapping and controlled token endpoint behavior.
